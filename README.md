# Chatbot Project

A simple chat interface built with React. Messages you send are answered by a bot running
locally in the browser — no backend or API keys required.

![React](https://img.shields.io/badge/React-19-61DAFB?logo=react&logoColor=20232A)
![Vite](https://img.shields.io/badge/Vite-6-646CFF?logo=vite&logoColor=5173FF)

## Features

- Chat window with a seeded welcome conversation
- Separate user and robot message bubbles with profile images
- Auto-scrolling to the newest message as the conversation grows
- Bot replies generated on the client via `supersimpledev`

## Getting started

Requires Node.js 20 or newer.

```bash
npm install
npm run dev
```

Vite prints a local URL (default `http://localhost:5173`) — open it in your browser.

### Scripts

| Command | Description |
| --- | --- |
| `npm run dev` | Start the dev server with hot module replacement |
| `npm run build` | Build the production bundle into `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run lint` | Run ESLint over the project |

## How it works

The full conversation lives in a single `useState` array in `src/App.jsx:7`. Each entry
looks like:

```js
{
  id: 'id1',
  message: 'hello chatbot',
  sender: 'user', // or 'robot'
}
```

State and the setter are passed down to `ChatInput`, which appends the user's message,
asks the bot for a reply, appends that reply, and clears the input
(`src/components/ChatInput.jsx:12`). `ChatMessages` maps the array to `ChatMessage`
bubbles and keeps the scroll position pinned to the bottom
(`src/components/ChatMessages.jsx:8`).

Responses come from `Chatbot.getResponse()` in the `supersimpledev` package, so replies are
rule-based and deterministic rather than generated by a language model.

## Environment variables

None are required to run the app today — there is no backend yet.

`.env.example` is the committed template for future variables. Copy it to `.env` to fill in
local values. `.env` and `.env.*` are git-ignored; never commit real keys.

Vite treats `VITE_`-prefixed variables as public and inlines them into the browser bundle at
build time, so they must never hold a secret. AI provider keys, database credentials, and
other sensitive values belong in unprefixed variables read by a server process, not in `src/`.

## Current status

The UI and message flow are working. Not implemented yet: message persistence across
reloads, timestamps, typing indicators, and keyboard submit (the button must be clicked).

The incremental migration architecture, decisions, phase checkpoints, and Phase 0
validation are documented in [docs/architecture.md](./docs/architecture.md). The existing
`supersimpledev` local response path remains in use; no backend or real AI provider is
configured yet.
